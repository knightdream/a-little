# 项目理念（中文翻译）

> 本文译自 [PHILOSOPHY.md](PHILOSOPHY.md)。文中的“我”指原文作者；分支目标与偏好均保留原文含义。

# `accurate` 分支

这个分支是对原版 `Doukutsu.exe`（v1.0.0.6）的纯粹反编译，因此，其理念没有太多需要解释的地方。

## 目标

最终目标是让项目能够生成一个与原版完全相同的 `.exe` 文件。这意味着不应加入自定义代码；理想情况下，反编译后的代码应当生成与原版相同的汇编代码；原有的错误也应保留，等等。

项目的另一个目标是记录《洞窟物语》的内部工作原理，因此代码应有适当的注释。同样，发现的错误也应记录下来，并提供用 `#ifdef FIX_BUGS` 条件编译包裹的修复代码。

## 对原始源码的还原程度

就我个人而言，我确实希望反编译代码在**功能上**忠实于原版，甚至生成相同的汇编代码，但我并不追求代码在**书写形式上**与原始源码完全一致。

尽管如此，我仍会尽量保留原来的函数名、变量名、变量声明位置以及源文件命名。

我不追求书写形式完全一致，部分原因是：从[已公开的 Organya 源码](https://github.com/shbow/organya/)中，我们可以了解到 Pixel 的代码风格，而我觉得这种风格**极其**难读。

## 语言

《洞窟物语》的开发者 Pixel 主要使用日语，但其代码中的变量名和函数名大多使用英语，只有极少数使用了罗马字日语。

已公开的 Organya 源码表明，Pixel 使用日语编写注释。不过，在本项目中，我更倾向于使用英语注释。

本项目使用的英语混合了美式英语、加拿大英语和英式英语。

# `portable` 分支

这个分支的发展方向与 `accurate` 分支不同，但两者仍然有许多共同的核心理念。

## 目标

虽然准确还原《洞窟物语》的原始代码仍是一项重要目标，但这个分支的重点是将游戏移植到其他平台，同时保留玩家在 2004 年体验到的游戏原貌。

简单来说，这个分支的存在，是为了让玩家不必准备一台老旧的 Windows XP 电脑，也能体验原汁原味的《洞窟物语》。

特别需要指出的是，这意味着原有的错误仍应保留。不过，影响跨平台移植的错误及其他编码问题应当修复。

作为对比，我认为这个分支与 Chocolate Doom 项目有许多相似之处。下面链接中的项目理念，也可能适用于这里：

[Chocolate Doom 项目理念](https://github.com/chocolate-doom/chocolate-doom/blob/master/PHILOSOPHY.md)

## 自定义代码

《洞窟物语》的原始源码使用 C++ 编写，但代码风格接近 C89，少数地方例外。向本项目添加的自定义代码也应沿用这种风格，不过不必严格限定为 C89。就我个人而言，我更喜欢使用 C++98 所允许的那部分 C99 写法。

我倾向于避免编译器专属的代码，因为可移植性更好的代码能够让所有编译器受益，也能避免代码库变得杂乱。
