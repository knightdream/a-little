# 借灯玩法与首关

首个版本只验证一件事：玩家是否愿意为了看清道路和线索，冒险举起一盏会暴露自己的灯。采用横版房间探索，保留现有 Unity 项目的移动基础。以下系统均为设计提案，不能视为已开发功能。

## 玩家循环

观察环境 → 在安全位置提灯辨认异常 → 记住通路或获得线索 → 放低灯避开巡查 → 到达下一间房并验证猜想。

灯的作用必须稳定，不能为了吓人任意失效。玩家失败后应能说清自己是被看见、发出声响还是走错路线。

## 第一版操作

| 操作 | 功能 | 当前代码情况 |
|---|---|---|
| A 和 D | 左右移动 | 已有 |
| 空格 | 跳跃低矮障碍 | 已有，需重新调整速度和跳跃高度 |
| E | 检查、对话、开门 | 待开发 |
| 鼠标右键或可重绑定按键 | 提灯或放低灯 | 待开发 |
| Shift | 蹲行，降低脚步声 | 待开发 |
| Esc | 暂停和设置 | 待开发 |

暂不把复杂连招、二段跳、反击和精确闪避加入首关。减少同时学习的操作，让玩家先理解环境规则。现有 J 射击在技术测试房间保留，在故事关卡里默认关闭。

## 灯的具体规则

放低灯时仍能看清脚下和近处障碍，环境不能变成全黑。提灯扩大照明范围，并显露夜村文字、路径和特殊对象。

首关灯不消耗燃料，以免新玩家因探索过久耗尽资源而卡关。是否加入灯油，等首关验证后再决定。

隐藏桥梁在提灯时显形并可通行。玩家站在桥上时，放低灯后保留短暂、清晰的消散提示，提示结束前可以再次提灯恢复。第一版先只做一段落下后能安全返回的教学桥，不使用无提示的必死坠落。

被照见的文字可以加入线索记录，避免要求玩家记住长段密码。关键线索重复查看不会消失。

## 提灯人的行为

| 状态 | 玩家能看到的提示 | 转换条件 |
|---|---|---|
| 巡查 | 缓慢行走，灯光扫过路径 | 发现灯光或近处移动后进入怀疑 |
| 怀疑 | 停步，朝来源转身，灯光增强 | 持续看到玩家则追逐；未确认则检查附近 |
| 追逐 | 加快步速，叫出主角的名字 | 玩家切断视线并藏好后进入搜索 |
| 搜索 | 在最后发现的位置附近徘徊 | 一段时间未发现玩家则恢复巡查 |

放低灯不是隐身。敌人已经看到玩家时，必须先借门、墙或遮蔽物切断视线。距离、方向和遮挡要参与判断，不能隔墙检测到所有提灯动作。

被抓后短暂淡出，回到最近的明确检查点。首关不扣除永久资源。无障碍选项可降低追逐速度，并提供声音对应的视觉提示。

## 首关流程

目标时长约 10 至 15 分钟，仅作为制作规模目标，需通过试玩计时修正。

```text
渡口小屋 → 村口灯桥 → 旧宅前院 → 堂屋与厨房 → 后院窄巷
 安全教学    灯路教学     环境异样      线索与谜题      短追逐
```

### 渡口小屋

玩家学习移动、交互，从沈婆处取得空灯并装入信中的灯芯。这里没有敌人。墙面上的水位线，只有提灯才显出“别替人点灯”几个字。

出口前设置安全检查点，并用一次明显反馈说明保存成功。沈婆教的是可验证的操作，不一次性讲完背景故事。

### 村口灯桥

普通视野只看到断桥。提灯后显现夜村桥面，过桥时远处出现一个提灯剪影，但此时不会追杀玩家。

桥下有可返回的浅滩，确保玩家第一次测试灯光不会遭受高惩罚。通过后回望，剪影已经移到旧宅门口。

### 旧宅前院

玩家发现门前姓名灯与湿鞋。第一次检查灯只能读到名字，提灯后才看见“已到家”。旁边的搬迁通知写着全村已断电，屋内却亮着电灯。

入口处再次保存。这一区域建立异常，不做战斗。

### 堂屋与厨房

目标是取到姐姐藏在相框后的信。柜门锁需要三块带家庭称谓的木牌按离家顺序摆放。

线索来自一张搬家记录：父亲在桥头先接走弟弟，母亲的衣物单独封存，姐姐一栏为空。灯下合照显示姐姐站在门内送别。第一版采用明确的三项排列题，并在错误时给出“记录对不上”的反馈，不用猜真实民俗知识。

为避免剧情年代含混，实际谜题制作时使用一张写明先后顺序的家用便条，称谓木牌只承担机关用途；不把推理出母亲死因作为开锁前提。

厨房传来母亲重复的招呼。玩家可从门缝看见案板自己起落，选择不靠近。完成谜题才触发门外的敲门声，阅读关键文字期间不会启动追逐。

取到的信只有短短两行：“我没出去。去学校，找我的名字。”画面将去学校设为下一目标。

### 后院窄巷

提灯人从堂屋进入，玩家从已经探索过的后门撤离。路线包含一个低障碍、一处能切断视线的转角和一个清楚可辨的藏身处。

这是第一次真正的追逐，不临时添加陌生按键。首次被抓后从旧宅出口前重试，已完成的谜题保持完成。

追逐结束，远处学校铃响。镜头停在街口新挂起的姓名灯，试玩结束，明确显示“第一章试玩结束”。

## 资源和开发范围

首关只需一名玩家、一种追踪敌人、五个连通小区域、一套灯光表现、一种排列谜题、一段简单对话流程和一个检查点系统。环境素材优先重复使用门、墙、木桥、灯和家具。

美术方向暂定为低分辨率像素画，冷灰环境与暖黄灯光形成对比。当前色块原型继续承担碰撞测试，不要求先完成正式美术再验证玩法。

音效首先只做脚步、敲门、提灯人的动作提示和少量环境声。首次版本不需要全角色配音。

## 对现有 Unity 项目的改造

| 现有模块 | 使用方式 |
|---|---|
| PlayerController | 保留移动与跳跃；将生命、输入和武器逐步拆开，避免一个脚本包办全部 |
| GameBootstrap | 保留测试房间入口，另建故事场景入口 |
| TestRoom | 保留为开发测试场景；故事房间用独立场景或房间配置制作 |
| Walker | 保留原型敌人；新增提灯人的巡查状态机，避免改坏原测试 |
| Projectile 与 ExperiencePickup | 留作技术实验；首关暂不启用 |

新增模块建议依次为：交互对象、提灯控制、显隐对象、追踪敌人、线索记录、检查点。每次只做一条可完整试玩的流程，不先搭建通用任务编辑器或复杂背包。

## 开发顺序与验收

1. 灯光试验房：同一位置反复提灯能稳定显示文字和桥；桥消失有提示，没有卡死点。
2. 单敌人试验房：可以观察巡查、主动吸引、切断视线并脱离搜索；隔墙提灯不会直接触发追逐。
3. 旧宅片段：取线索、解谜、触发敲门、逃离串成完整流程；抓到后无需重做谜题。
4. 加入正式声音和少量美术，请不了解设计的人试玩，观察是否能自行理解灯的代价和下一目标。

进入第二章制作前，先验证首关是否足够有趣且清楚。完整故事可以先写完，完整游戏不必同时开工。
